# Findings
- Desktop live feasibility outcome: user explicitly confirmed Full OAuth grant received in the header-aligned native experiment after prior credential rejection. Record as user-reported provider acceptance/full-grant acquisition for this test; do not claim every header is required, Android login works, primary identity/trading authorization is established, or production integration/storage/renewal has been live-tested. The experiment discards its grant rather than persisting it.
- User diagnostic: HTTP400, error=absent, reason=credentials_rejected, fields ending literally detai. User confirms fresh browser email/password followed by mobile-device approval succeeds. Native initial request gets generic rejection before a supported verification workflow; neither bad password nor anti-bot/client policy is established. Compared actual native wire headers with pinned upstream globals.py: Accept, Accept-Language, X-Robinhood-API-Version, User-Agent and form charset differed. Added7 loopback header rows spanning initial/final grants, inquiry GET and JSON machine/continuation; observed5 RED mismatches, then corrected those selected headers. Qt still negotiates compression/connection/TLS; this is reference-client fidelity, NOT a proven remedy for provider rejection.
- A source-shared native client does not depend on WebView pre-navigation/cookie APIs. Qt Core/Network/Widgets modules exist for selected macOS and Android kits; parent compiled the experiment on macOS Qt6.12 and Android ARM64 Qt6.11.2.
- Android Qt toolchain selects its NDK using ANDROID_NDK_ROOT, not CMAKE_ANDROID_NDK alone. Initial configuration fell back to an unavailable SDK-build-machine /opt NDK and incorrectly selected host compiler, producing EGL/GLES dependency errors. Reconfigured this new build with --fresh and the explicit local ANDROID_NDK_ROOT; correct Clang Android compiler/dependencies resolved without installing packages or changing production.
- Dedicated Android APK currently packages arm64-v8a libssl_3.so, libcrypto_3.so and Qt OpenSSL TLS plugin; apksigner verification passed. aapt confirms distinct com.publicstradinginterface.robinhoodauthspike, min SDK28/target36. These are packaging checks, not device/provider TLS proof.
- Compact UI regression observed RED (horizontal overflow134px at360px); shortened the consent checkbox while retaining a wrapped destination/consent explanation. Rebuilt UI tests/offline smoke GREEN2/2. Never clicked live login.
- Upstream protocol is unofficial, password-based and may fail despite valid ordinary-browser credentials. Never infer approval on timeout or copy its unbounded push poll. Existing complete-grant codec can be reused without linking the production network/order engine.
- This experiment intentionally retains no credentials/tokens, performs no identity/account/trading reads, and does not remove the production Android gate. Platform secure storage and Android resume/device behavior remain integration/runtime tasks.
