# Findings
- The prior experiment's successful complete-grant acquisition is user-confirmed on desktop. This does not yet establish production identity/account validation, persistent credentials, refresh after restart, Android runtime or trading acceptance.
- Existing RHOAuthGrant version1 strictly validates exact schema and separates complete provider response from inherited client/device/scope/refresh context. Native credentials need a separately versioned secure envelope namespace; do not put password/email fields into the original provider response.
- Existing RHQtKeychainStore uses stable service PublicsTradingInterface.RobinHood with RobinHoodAuthX slots; existing SecureCredentialLocker supplies encrypted RAM PendingCredentials and legacy encrypted-file cleanup. One combined keychain record avoids a second persistent password-store transaction.
- Existing session metadata stores account_name in plaintext. New native profiles must persist an opaque label plus keychain-backed-label flag and load verified email from the secure record, or the email would still be duplicated unencrypted. Keep existing legacy profiles readable; migrate only on successful native reauthentication.
- Existing identity/account validation, credential reservation, revision/digest binding, rotation retention and commit gating remain required. Renewal must inherit credentials in the secure envelope without adding them to refresh request bodies.
- Known old cancellation branch may clear an error from a synchronously completed replacement save after idle publication; read-generation/busy checks alone do not protect non-read replacements. Include exact regression and move retired cleanup before final idle notification.
- Main bundle identifier remains trb.appPublicsTradingInterface; do not change app identity/service/key labels during this integration. OS-backed credentials outside the bundle are designed for normal in-place updates, not guaranteed uninstall/keychain-deletion/signing-identity migration recovery.
- Root applet State must declare native client before session manager so session teardown can cancel it safely; trade controller still destroys first. Historical browser code can remain for compatibility tests, but production QML/context/runtime must not instantiate it.
