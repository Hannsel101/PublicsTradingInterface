# Findings
- Architecture question only, no login implementation change authorized: current upstream authentication.py directly POSTs a password grant, handles verification workflows and persists access/refresh/device context; provider acceptance is still untested for this desktop client. Native port would avoid WebView-specific execution and could acquire a full grant if accepted, but cannot guarantee credential acceptance or remove MFA/device approval. RFC9700 section2.4 prohibits password grants in modern OAuth best practice; RFC8252 favors external-browser authorization with supported redirect/code flow. Do not invent a supported Robinhood authorization-code integration or call ordinary external-browser sign-in a token handoff. Any native route is an unofficial compatibility experiment, not a verified repair.
- Release console paste shows webpage Fetch/CSP failures for advertising/analytics/event destinations, not evidence of a C++ GET or an authentication HTTP response. Confirmed packaged Login remains Enabled=false; typed refresh is POST. Verified upstream robin_stocks master directly via TLS curl: profiles.py load_user_profile calls request_get (line241), helper.py request_get calls SESSION.get (lines275/282). Translating that client to C++ retains authenticated GET reads; Fetch API terminology does not mean a publicly supported API. web_extract failed due configured search-only extraction backend; used primary-source TLS curl without provider authentication or credential-bearing requests. Browser secondary-only initial acquisition remains separate from these console warnings.
- New user login report: error appears on Robinhood webpage inside the app; same account signs in successfully in a regular browser. Supplied Chromium log has TLS net_error -113, denied requestStorageAccess and marketing/payment feature warnings, but no failing hostname/login HTTP status or provider response. Chromium primary error definitions map -113 to SSL_VERSION_OR_CIPHER_MISMATCH; storage-access denial concerns embedded third-party state, not proof of bad credentials or the login cause. No code fix/provider-rejection diagnosis established; preserve TLS checks and do not solicit credentials. Separate this initial embedded-login failure from refresh lifecycle and the earlier cancellation-review blocker.
- Qt direct signals require operation admission gates to be CHECKED by every unrelated public mutator, not only SET before notification. An error-clearing observer can start a second credential save before busy is published; a boolean pending-IO flag cannot safely account for two writes sharing a reservation. Cancellation must not access retired manager state after its final idle notification.
- Current applet is Qt6/C++; there is no native Python framework token state to bypass. Existing browser login captures only WebSecondaryBearer. Existing QtKeychain abstraction stores raw bearer strings at RobinHoodAuthX; TokenRefresh is disabled in packaged config.
- Existing build policy is a separate explicit RELEASE macro on rh_network_engine; successful primary renewal can satisfy session authorization, but must not change Debug preview/Release policy or make secondary-only entries trade-capable.
- Verified RFC6749 section6 over system TLS curl: form-urlencoded grant_type=refresh_token and refresh_token; token bound to original client; optional omitted scope retains original; requested scope cannot expand; rotated refresh replaces old, which server may revoke. Lifetimes are server-issued, not fixed by local storage.
- web_extract failed because configured native backend is search-only. Used verified-TLS curl of official rfc6749.txt instead; no TLS weakening.
- Full initial OAuth grant must enter through C++-only acceptOAuthGrant(response,clientId,deviceToken); a missing refresh token cannot be manufactured from a secondary cookie. Existing browser acquisition limitation is separate from renewal support.
- Shared implementation interface and strict ownership are in implementation-contract.md. Agent A owns value codec/network/config/tests; Agent B owns session lifecycle/tests; parent owns CMake/UI/docs/integrated verification.
