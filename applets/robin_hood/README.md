# Robin Hood session applet

`config/robinhood-api.json` contains the endpoint URLs, HTTP verbs, body encodings, and raw request headers observed in `jmfernandes/robin_stocks` at commit `1b4ef98` (2026-02-10). This is an **unofficial source map**, not confirmation that the service still accepts those requests. In particular, upstream has no token-refresh request or `Device-Hardware-ID` header; `TokenRefresh` is disabled rather than invented.

`RHNetworkEngine` has no compiled-in brokerage URL or header name. The applet loads the packaged `:/robinhood/config/robinhood-api.json` at runtime; offline tests can load a loopback JSON file instead. `send(endpointKey, values, query, body, &error)` returns a `QNetworkReply *` on success, or null and a non-secret error string if dispatch was rejected; the caller handles completion and calls `deleteLater()` on the reply. Loading configuration sends nothing. `BodyDefaults` provides non-secret, endpoint-specific form or JSON fields that callers can override.

`values` supplies URL placeholders (percent-encoded as path/query components) and header placeholders (such as `token_type` and `access_token`). `query` adds query parameters; `body` is a `QVariantMap` encoded according to the endpoint's `BodyEncoding`: `form`, `json`, or `none`. Form booleans use Python Requests-compatible `True`/`False`; null form values are omitted. No credentials or tokens belong in this JSON file. Only HTTPS endpoints and loopback HTTP for offline tests are accepted, and redirects are not followed automatically.

`RobinHoodApplet` registers in the existing one-window Launcher, hosts a dark teal/lime session picker, password/MFA-code login form, and read-only account overview. Auto Mode is disabled and no saved-session timer is displayed. During device approval **only**, the login view displays a 3-minute countdown and cancel action. Orders are **not** wired to this applet; no buy/sell or refresh-token workflow is implemented.

`RHSessionManager` owns an expiry-aware `QAbstractListModel` with `accountName`, `sessionIndex`, `expiresAt`, and `isExpired` roles. `QStandardPaths::AppDataLocation/robinhood/sessions.json` contains only index, email/name, UTC ISO creation/expiry and non-secret token type; its commits use `QSaveFile`. Corrupted metadata is never overwritten. Tokens are stored separately by `RHQtKeychainStore` under `RobinHoodAuth0`, `RobinHoodAuth1`, … in the `PublicsTradingInterface.RobinHood` service, with insecure fallback disabled. A failed keychain write does not create metadata; a failed metadata write attempts to delete the just-written keychain entry. Deletion is idempotent if the keychain entry is missing, and only after the metadata update succeeds does the reauthentication UI open. If metadata deletion fails, the old entry remains for retry.

The sign-in request asks for at most 30 days, but the stored expiry is limited by the **actual server `expires_in` grant**. A missing/invalid grant is rejected. OAuth responses containing `verification_workflow.id` initiate the upstream Pathfinder user-machine/inquiry/push-status/continue sequence; direct `challenge_id` plus a push/device-approval type can poll the configured push endpoint. Both variants keep one request in flight at a time, poll at 2.5-second intervals, stop after 180 seconds, and require a final OAuth token before saving anything. An approved Pathfinder workflow retries the original OAuth request with the same device token. Declines, unsupported SMS/email challenges, missing final tokens, cancellation and timeout fail closed. The password is retained in memory only while the asynchronous handshake needs that final retry; the UI clears its password and MFA field after submission. After keychain storage, the applet reads the token asynchronously and verifies it using the configured read-only `Accounts` endpoint before showing the overview. Returning Home during approval aborts polling; saved credentials remain untouched. Live Robinhood compatibility is unverified: C++ tests use a fake credential store and a loopback HTTP server, and QML tests use mock facades.
