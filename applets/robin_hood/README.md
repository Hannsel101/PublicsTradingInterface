# Robin Hood session applet

**Android sign-in is disabled pending a native pre-navigation interceptor.** QtWebView URL-change notifications occur after dispatch and are not a security boundary. The retained Android WebView/JNI scaffolding is not selected in production. Desktop WebEngine uses a pre-navigation gate.

`config/robinhood-api.json` contains the endpoint URLs, HTTP verbs, body encodings, and raw request headers observed in `jmfernandes/robin_stocks` at commit `1b4ef98` (2026-02-10). This is an **unofficial source map**, not confirmation that the service still accepts those requests. In particular, upstream has no token-refresh request or `Device-Hardware-ID` header; `TokenRefresh` is disabled rather than invented.

`RHNetworkEngine` has no compiled-in brokerage URL; its platform-specific User-Agent overrides any configured value. Configured `Accept-Encoding` is ignored so Qt negotiates supported encodings and automatically decompresses responses before JSON parsing. The applet loads the packaged `:/robinhood/config/robinhood-api.json` at runtime; offline tests can load a loopback JSON file instead. `send(endpointKey, values, query, body, &error)` returns a `QNetworkReply *` on success, or null and a non-secret error string if dispatch was rejected; the caller handles completion and calls `deleteLater()` on the reply. Loading configuration sends nothing. `BodyDefaults` provides non-secret, endpoint-specific form or JSON fields that callers can override.

`values` supplies URL placeholders (percent-encoded as path/query components) and header placeholders (such as `token_type` and `access_token`). `query` adds query parameters; `body` is a `QVariantMap` encoded according to the endpoint's `BodyEncoding`: `form`, `json`, or `none`. Form booleans use Python Requests-compatible `True`/`False`; null form values are omitted. No credentials or tokens belong in this JSON file. Only HTTPS endpoints and loopback HTTP for offline tests are accepted, and redirects are not followed automatically.

`RobinHoodApplet` now opens the official `https://robinhood.com/` site inside its own browser layout for Add Account and reauthentication. Credentials, CAPTCHA and device approval are entered/completed on that site, not in app-owned text fields. Direct headless password login and old challenge endpoints are disabled. Auto Mode/orders remain unavailable. Publics authentication/trading source is unchanged; shared startup only initializes the Robinhood browser runtime.

`RHBrowserLogin` captures only `__Host-Web-App-Secondary-Access-Token` through a C++ callback, never through JavaScript or token-valued QML signals/properties. Desktop uses a fresh off-the-record WebEngineProfile and native QWebEngineCookieStore; The disabled Android scaffolding uses QtWebView and native CookieManager.getCookie for the fixed official URL on the Android UI thread. Generation checks, trusted HTTPS navigation, exact cookie name/root host/path and secure-cookie policy reject stale or unsafe captures. Android clears only the named secondary cookie before loading the site, not unrelated application cookies.

The separate `RHAccountModel` contains one read-only item per account returned by `/accounts/`, with `displayName`, `accountNumber`, and formatted `currentBalance` roles. It distinguishes Roth and Traditional IRAs using available type, retirement, description, or nickname metadata; a non-retirement margin account is labeled Individual Investing. When subtype metadata is absent, it does **not** guess which kind of IRA a cash account is. Balances prefer `total_equity`/`equity`, then cash balance for non-margin accounts. Missing or invalid amounts display “Unavailable,” never a fabricated `$0.00`. These values are a snapshot of the most recent Accounts response, not a live streaming quote; Phoenix balances are not fetched separately.

`RHSessionManager` validates the captured token with read-only UserProfile and Accounts requests before QtKeychain storage. Reauthentication additionally verifies the stable user ID against the selected saved account. Cancellation, rejection or account mismatch leaves the saved session unchanged. Tokens retain the `RobinHoodAuth0`, `RobinHoodAuth1`, ... naming in the `PublicsTradingInterface.RobinHood` service with insecure fallback disabled. Non-secret AppData `robinhood/sessions.json` records labels, stable IDs, timestamps, legacy device metadata and a distinct `WebSecondaryBearer` transport marker. Browser sign-in does not read or create password records in `profiles.dat`. After validation, the browser closes and the non-cancellable keychain/metadata commit finishes; the saved picker offers Start Session. Cookie expiry is capped locally at 24 hours; cookies without expiry (including Android CookieManager results) get one hour. These are cache bounds, not OAuth-grant or live-provider guarantees.

## Persistence contract

`SecureCredentialLocker` and its QtKeychain-protected AES-256-GCM `profiles.dat` format remain only for legacy data compatibility/cleanup, not browser authentication. Existing passwords are not silently erased or reused. QtKeychain uses the OS credential facility, not guaranteed AES Secure Enclave storage. Reinstall/update recovery requires retained AppData, stable signing/application identity and accessible keychain entries. Qt/framework/browser/network copies prevent a promise of complete RAM erasure. See `locker-security.md` for historical format details.

## Secondary-token transport limitation

The secondary cookie is not the official web app's primary API access token. `sendAuthenticated()` provisionally maps it to `Authorization: Bearer <value>` only for configured GET `api.robinhood.com/user/` and `/accounts/` verification. This mapping is unverified against a live account and can be rejected: HTTP 401/403 yields an explicit error and **no saved session**. No verified Phoenix route/secondary transport contract was available, so none is fabricated or enabled. Authenticated requests enforce host/path restrictions, manual redirects and cookie loading/saving disabled; loopback requires an explicit test-only flag. No token goes into URLs or logs.

## Browser modules and isolation

Desktop requires matching Qt WebEngineQuick; QML uses WebEngineView rather than the QWidget-only QWebEngineView. Android requires Qt WebView and initializes it after QGuiApplication. Missing modules expose an explicit unavailable backend with no credential fallback. In this environment, Qt6.11.2 desktop has WebEngine; the installed Qt6.12 desktop SDK does not.

Desktop profiles are memory-only, reject certificate errors and external top-level navigation, and allow browser subresources/frames needed by the provider. Android QtWebView uses an application-wide native cookie jar rather than a per-login profile: only the named secondary cookie is reset, and account switching/site logout remains controlled by the official website. CookieManager does not return expiry/attributes; the native browser enforces the `__Host-` contract. The app does not globally erase cookies or website storage belonging to other applets.

A real browser does **not** guarantee embedded-login acceptance, CAPTCHA completion or a push notification. No gr_token is forged or CAPTCHA bypassed. Offline tests use synthetic cookies, injected keys/stores, mocked QML browser content and loopback HTTP; no real credentials/keychain entries/trades are accessed. Native capture, Android compilation and live provider/API acceptance are separate verification layers.
